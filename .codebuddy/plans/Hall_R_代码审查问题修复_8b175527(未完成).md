## 用户需求
用户对 `/home/qcy/Project/code/Tangential/PZT_Hall/Hall_R` 做了修改（`tactile_sensor.py` 新增 Hall 解码 `decode_hall_block`、多线程采集、状态统计 `get_status`；`main.py` 新增每秒打印与故障诊断逻辑），已完成代码审查。根据审查结果，需要修复以下两个健壮性问题：

## 核心修复项
1. **`main.py` 竞态条件（真实 bug）**：`latest_response_payload` 初始为 `None`，当主循环 `read_data()` 返回 `None` 但一帧恰好在 `get_status()` 调用前通过校验入队时，`valid_frame_count > 0` 会导致代码走到 `decode(None)` 并抛出 `TypeError`。需在 decode 调用前增加 `None` 保护。
2. **`tactile_sensor.py` 缓冲区无容量上限**：`_rx_buffer` 在 `_response_loop` 中 `extend` 后缺少参考版本原有的 `MAX_RX_BUFFER_LEN` 截断保护，固件异常时可能导致内存堆积。需恢复容量上限逻辑。

## 验证目标
- 修复后两个文件通过 Python 语法检查（`ast.parse` / `py_compile`）
- 修复不改变正常数据路径下的行为（每秒打印、故障诊断逻辑保持不变）



## 技术方案
### 修复 1：main.py 竞态条件保护
位置：`/home/qcy/Project/code/Tangential/PZT_Hall/Hall_R/main.py` 的 `main()` 函数（约第 125~170 行之间）。

在 `valid_frame_count <= 0` 的分支之后、`decode(latest_response_payload)` 调用之前（即 invalid_frame 警告处理完毕后）增加保护：

```python
if latest_response_payload is None:
    # 竞态窗口：统计显示有有效帧但主循环尚未取到数据
    active_problem = None
    previous_status = status
    print_window_start_time = current_time
    continue
```

该保护逻辑简单直接：若主循环尚未取到任何帧数据，重置窗口状态并等待下一个 1 秒窗口，不做打印也不抛异常。

### 修复 2：tactile_sensor.py 缓冲区容量上限
位置：`/home/qcy/Project/code/Tangential/PZT_Hall/Hall_R/tactile_sensor.py` 的 `TactileSensor` 类。

1. 在类中添加常量（与已删除的参考版本 `tactile_sensor copy.py` 一致）：
```python
MAX_RX_BUFFER_LEN = max(
    4096,
    RESPONSE_PROTOCOL.RESPONSE_FRAME_LEN * 16,
)
```
2. 在 `_response_loop` 的 `with self._buffer_lock:` 块内、`self._rx_buffer.extend(received_data)` 之后添加截断：
```python
if len(self._rx_buffer) > self.MAX_RX_BUFFER_LEN:
    del self._rx_buffer[:-self.MAX_RX_BUFFER_LEN]
```

截断在锁内执行，与现有锁策略一致；保留最近的数据（`del [:-N]` 保留尾部），帧头搜索仍可正常进行。

### 实现要点
- **最小改动原则**：两处修复均为插入式修改，不重构任何现有逻辑，不影响用户已完成的故障诊断架构
- **行为保持**：正常路径下 `latest_response_payload is None` 的保护分支几乎不会触发，仅在竞态窗口命中时跳过一次打印
- **锁一致性**：截断逻辑必须在 `_buffer_lock` 内，与 `_parse_response_buffer` 的访问互斥，避免并发修改 `bytearray`
- **验证方式**：`python3 -m py_compile`（或 `ast.parse`）对两个文件做语法检查；运行时验证需要 `/dev/ttyUSB0` 硬件设备，不在本次范围内
